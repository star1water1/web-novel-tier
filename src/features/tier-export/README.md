# 티어표 엑셀 내보내기·가져오기 (tier-export)

순위 탭의 표를 xlsx로 저장한다. 두 번째 출력부터 지난 출력본과 비교해 색을 칠한다. 밖에서 고친 파일의 티어, 순서, 읽은 화수를 다시 가져올 수 있다.

| 파일 | 내용 |
|---|---|
| `xlsxWriter.js` | 시트 하나짜리 xlsx 생성. 라이브러리 없이 ZIP(압축 없음)과 XML을 직접 쓴다 |
| `diff.js` | 지난 출력본과 비교해 신규, 상승, 하락, 화수 변화, 삭제를 가린다 |
| `sheet.js` | 작품 → 행 가공, 행 → 시트 모양과 색 |
| `store.js` | 출력 기록 표, 백업 항목 `XS`, 가져오기 적용과 되돌리기 |
| `TierExportScreen.js` | 변동 요약, 비교 기준 선택, 폴더 저장 화면 |
| `xlsxReader.js` | xlsx 읽기. 압축 풀기, UTF-8, XML을 직접 처리한다 |
| `importPlan.js` | 파일과 출력 기록, 앱의 표를 맞춰 무엇을 바꿀지 정한다 |
| `TierImportScreen.js` | 파일 선택, 변경 미리보기, 적용과 되돌리기 화면 |

## 색

| 상태 | 범위 | 색 |
|---|---|---|
| 신규 | 행 전체 | `FFF7CC` |
| 순위 상승 | 행 전체 | `ECF8D4` |
| 순위 하락 | 행 전체 | `FDEADB` |
| 화수 변화 | 읽은 화수 칸만 | `ECF8D4` (상승 행에서는 `CDE8A5`) |

첫 출력은 칠하지 않는다.

## 판정

순위가 바뀐 원인은 찾지 않는다. 티어 방식마다 쓰는 데이터가 달라도 결과인 티어와 순서는 같은 모양이라, 그것만 저장하고 비교한다.

1. 지난 표에 없으면 신규, 이번 표에 없으면 삭제다.
2. 남은 작품 중 서로의 순서를 유지한 가장 큰 묶음을 찾는다. 이 묶음은 순위 숫자가 바뀌었어도 밀린 것으로 본다.
3. 묶음에 들지 못한 작품이 주체다. 넘어선 작품 수로 방향을 정한다.
4. 티어가 바뀌면 순서가 그대로여도 칠한다. 지난 티어가 지금 구성에 없으면 방향을 지어내지 않는다.

두 출력본이 모두 `rating`으로 순위를 정했으면(매칭, 비율) 점수가 그대로인 작품을 묶음에 먼저 넣는다. 직접 배정과 혼합은 `rebalanceTierOrder`가 `manual_order`를 다시 매기므로 값 변화로 가릴 수 없어 순서만 본다.

결과만으로는 구분되지 않는 경우가 있다. 두 작품이 맞바뀌면 하나만 칠하고, 짧게 많이 움직이면 오판이 늘고, 큰 묶음이 조금 움직이면 밀려난 쪽이 칠해진다. 원인을 정확히 알려면 순위가 바뀌는 모든 경로에 기록을 넣어야 해서 채택하지 않았다.

## 지키는 것

- 기준은 파일을 쓰고 다시 읽어 확인한 뒤에만 남긴다. 저장에 실패하면 지난 기준이 그대로다.
- 같은 내용을 다시 뽑으면 색이 사라지므로, 출력 기록을 20개까지 두고 비교할 출력본을 고르게 한다.
- 화면을 닫으면 보내기를 했어도 폴더 권한을 해제한다. 받는 앱은 읽기 권한을 따로 받는다.
- 화면은 `Alert`를 쓰지 않는다. 저장은 `isBlocked`를 확인하고, 폴더 선택 뒤에 슬롯이 바뀌었으면 멈춘다.
- 새 표는 `doClearAll`, 전체 초기화, 선택 초기화, `IMPORT_SNAP_TABLES`에 함께 등록한다. 표를 추가하면 `TIER_EXPORT_TABLES`에 넣는다.
- 순서는 App.jsx가 순위 탭과 같은 `tierRank` → `compareWithinTier`로 정렬해 넘긴다.

## 가져오기

내보낸 파일의 숨긴 열(I열)에 작품 ID가, 그 머리글에 `작품ID:<출력본 ID>`가 들어 있다. 이 ID로 출력 기록을 찾아 비교한다.

| 비교 | 처리 |
|---|---|
| 파일 = 출력 기록 | 고치지 않은 칸이다. 앱이 그 뒤 달라졌어도 건드리지 않는다 |
| 파일 ≠ 출력 기록, 앱 = 출력 기록 | 파일 값을 쓴다 |
| 파일 ≠ 출력 기록, 앱 ≠ 출력 기록 | 충돌. 기본은 앱 값이고 행마다 파일 값을 고를 수 있다 |
| 파일 = 앱 | 이미 같다. 아무것도 하지 않는다 |

출력 기록이 없으면(옛 파일, 다른 슬롯, 20개를 넘어 지워진 기록) 앱 값과 바로 비교하고 충돌을 가리지 못한다고 알린다.

- **작품 찾기:** 작품 ID로 찾고, 모르는 ID나 ID 없는 행은 제목이 정확히 하나일 때만 쓴다. 복원하면 ID가 새로 만들어질 수 있어서다. 같은 작품이 여러 행이면 모두 건너뛴다.
- **열:** 위치가 아니라 머리글로 찾는다. 없는 열은 읽지 않고 값을 유지한다.
- **순서:** 행 순서를 따르고 순위 칸은 읽지 않는다. 어긋나면 알린다. 티어 안에서 순서를 유지한 가장 큰 묶음을 빼고 옮기므로 앱에 새로 추가된 작품이 자리를 지킨다. 티어 칸만 고쳐 다른 티어 자리에 남은 행은 그 티어 맨 뒤로 간다.
- **티어 방식:** 티어와 순서는 직접 배정과 혼합에서만 받는다. 내보낸 뒤 방식이 바뀌었으면 받지 않는다. 혼합에서 옮기지 않은 작품은 `manual_tier`를 고정하지 않는다.
- **받지 않는 것:** 작품 추가와 삭제, 제목·플랫폼·대장르·작가. 파일에서 지운 행은 삭제가 아니다. 잘못된 칸은 행 번호와 이유를 보여 주고 건너뛴다.
- **적용:** 전후 값을 표에 쓴 뒤 `UPDATE` 한 문장으로 하므로 전부 적용되거나 전부 그대로다. 미리보기 뒤 앱이 달라졌으면 적용하지 않고 다시 보여 준다. 시스템 경로라 `enqueueVerification`을 부르지 않는다.
- **되돌리기:** 가장 최근 가져오기만 된다. 그 뒤 앱에서 또 고친 화수는 지우지 않고 개수를 알린다. 기록은 5개까지 두며 백업에 넣지 않는다.
- **새 표:** `tier_import_apply`, `tier_import_apply_item`은 `TIER_EXPORT_TABLES`에 있어 초기화와 복원 스냅샷이 함께 처리한다.

## 확인 범위

`tests/tier-export.test.mjs`는 판정, 가공, xlsx 구조만 본다. `--write-sample <경로>`로 시험 파일을 만들 수 있다. `tests/tier-import.test.mjs`는 압축 풀기, 파일 읽기, 변경 판정, 진짜 SQLite에서의 적용과 되돌리기를 본다. 실제 파일이 열리는지와 실제 엑셀에서 고친 파일은 프로그램에서, 폴더 저장과 파일 선택은 기기에서 확인해야 한다.
