## 세션 프로토콜 — "다음 작업 진행해줘"

사용자가 **"다음 작업 진행해줘"** (또는 "다음 거", "계속 진행" 등 유사 문구)라고만 입력하면 아래를 수행한다. 추가 질문 없이 시작하되, 🅓 작업은 **착수 전에** 카드의 선택지를 사용자에게 물어본다.

1. **작업 선택**: 순서표에서 `🔶`을 먼저, 없으면 가장 위의 `⬜` 또는 `🅓`를 연다. 사용자가 지목하면("T25 해줘") 그 작업을 우선한다.
2. **사전 검증 — 설계를 믿지 마라**: 카드의 전제를 실제 코드로 하나씩 확인한다. 카드의 줄번호는 **v7.58.4 시점, 헤더 이동(S1) 전 값**이라 실제와 크게 다르니 코드 문자열·함수명으로 Grep한다. 전제가 깨졌으면 구현하지 말고 카드의 설계부터 고친다. 문제 자체가 사라졌으면 `⊘`로 바꾸고 넘어간다.
3. **구현**: `CLAUDE.md` 규칙을 따른다. 가이드와 실제 코드가 다르면 코드가 우선이고, 차이를 카드에 남긴다.
4. **사후 검증**: `CLAUDE.md`의 검증 명령을 통과하고, 카드의 완료 기준을 데이터 흐름을 따라 확인하고, 수정한 함수의 호출처를 모두 Grep해 회귀를 확인한다. 실패하면 완료 처리하지 않는다. 막히면 `🔶`과 막힌 지점을 남긴다.
5. **기록**: `docs/history.md`와 `APP_VERSION`을 갱신하고, 순서표 상태를 바꾸고, 카드 '진행 기록'에 1~3줄 남긴다(버전, 설계와 달라진 점, 남긴 것).
6. **커밋**: 작업 브랜치에 `fix(도메인): 요약 (T-NN)` 형식으로 커밋한다.

한 세션은 순서표 한 행이 기본이다. `[묶음가능]` 카드는 여유가 있으면 이어서 한다.

### F1 ✅ — 공유 파일 삭제 보호

**대상**: S3의 🔴 13곳과 프리셋 배경 2곳. 슬롯을 복제하면 DB만 복사되어 양쪽이 같은 파일을 가리킨다. 복제본에서 작품을 지우면 원본의 명대사 이미지가 사라지고, 복제본에서 미사용 표지를 지우면 원본의 표지가 사라진다. 프리셋 배경을 쓰는 명대사를 빠른 편집한 뒤 그 작품을 지우면 프리셋 배경과 그 파일을 쓰는 모든 명대사의 배경이 사라진다.

**설계**: `deleteGalleryFilesUnusedByOtherSlots`를 넓혀 헬퍼 하나로 처리한다. 모든 슬롯 DB(활성 포함)의 `novels`, `planned_novels`의 `cover_image`와 `memorable_quote`, `gallery_images.file_path`, 프리셋 설정에서 파일 이름 참조를 찾고, 어디서도 안 쓰는 파일만 지운다. 슬롯 DB를 하나라도 못 읽으면 아무것도 지우지 않는다. 파일이 남는 쪽이 잃는 쪽보다 낫다.

**전제**: 호출 시점에 해당 행이 이미 삭제됐는지(활성 슬롯도 검사하므로), 프리셋이 `app_meta`의 어느 키에 있는지, 대량 삭제에서 슬롯 DB를 몇 번 여는지 확인한다. 자동매칭 중에는 큐 불변조건을 지킨다.

**완료 기준**: 복제 슬롯에서 작품·표지 삭제 후 원본 파일 유지(폰 확인) · 어느 슬롯도 안 쓰는 파일은 삭제 · DB를 못 읽으면 삭제 안 함 · 호출처 15곳 전환 · `npm test` 통과

**진행 기록**:
- 2026-11-02 · 에뮬레이터(Android 15)의 릴리스 빌드에서 실제 슬롯 복제와 화면 조작으로 확인했다. 복제본에서 작품 단건·일괄 삭제와 미사용 표지 삭제 뒤 원본 파일 유지, 예정작 단건 삭제, 같은 슬롯 두 작품의 공유 이미지, 기본 서식 초기화, 손상된 슬롯 DB가 있을 때 삭제 안 함, 마지막 참조가 사라지면 삭제까지 모두 통과. 예정작 일괄 삭제, 편집 저장 경로, 실제 사진, 대량 데이터의 속도, 실제 폰은 확인하지 않았다.
- 2026-11-02 · 사용자가 F1이 포함된 v7.59.27을 실제 폰에 설치해 "잘 됐어"라고 확인했다. 복제 슬롯의 삭제 시나리오를 폰에서 따로 돌려 본 것은 아니다.
- 2026-11-02 · v7.59.26 코드 완료. 활성 슬롯의 프리셋은 DB 저장이 늦을 수 있어 메모리의 `appSettingsRef`로 본다. 다른 슬롯은 `app_meta`의 `app_settings`를 본다. 예정작·일괄 삭제는 파일 삭제를 행 삭제 뒤로 옮겼고, 표지도 행을 먼저 지운다. `tests/shared-files.test.mjs` 추가. 이미 지워진 파일은 되살리지 못한다. 보호로 남은 파일은 마지막 참조가 사라져도 자동으로 지워지지 않는다.

**진행 기록**:

### F2 ✅ — 삭제 되돌리기와 이미지 파일

**현황**: `removeNovel`은 파일을 즉시 지우고 되돌리기를 제공한다. 되돌리면 작품 행은 돌아오지만 갤러리와 명대사 이미지는 복구되지 않는다 (코드 주석이 인정). 착수 때 확인한 결과, 되돌리기가 있는 삭제는 `removeNovel`뿐이고(`batchDelete`, 예정작 삭제에는 없다) 되돌리기 기록은 메모리에만 있어 앱을 끄면 사라진다. 갤러리는 파일뿐 아니라 행도 복원되지 않았다.

**선택지**:
- **A (권장)**: 되돌리기 기록이 사라질 때 파일을 지운다. 되돌리면 이미지까지 돌아온다. F1 헬퍼를 쓴다
- **B**: 현상 유지 + 되돌리기 전에 이미지는 복구되지 않는다고 안내

**진행 기록**:
- 2026-11-02 · v7.59.28. 사용자가 A를 골랐다. 파일 삭제 시점을 `removeNovel`에서 되돌리기 기록이 사라지는 시점으로 옮겼다. 기록의 변화를 `useEffect` 한곳에서 감시해 넘침·비우기·슬롯 전환·초기화·복원을 함께 처리하고, 대기 목록을 `undo_pending_files.json`에 남겨 재시작 때 지운다. 설계에 없던 추가: 갤러리 행 복원, 대기 중 다른 삭제 경로의 파일 보호, 플랫폼 기본 표지를 참조로 인정.
- 에뮬레이터(Android 15)의 릴리스 빌드에서 시험 데이터를 DB에 넣고 화면으로 삭제·되돌리기를 조작해 파일과 행을 확인했다. 되돌리면 파일과 갤러리 행 복원(갤러리 화면 표시 포함), 기록 비우기, 강제 종료 후 재시작, 넘침(크기 1), 대기 중 '미사용 표지 전체 삭제' 뒤 되돌리기, 슬롯 전환(복제본이 쓰는 파일은 유지, 아무도 안 쓰는 파일만 삭제) 모두 통과.
- 확인하지 않은 것: 실제 사진, 실제 폰, 초기화·복원 경로의 화면 동작, 명대사 이미지의 화면 표시(파일과 행만 확인), 라이브러리 행이 지워진 표지가 기록이 사라질 때 지워지는지(node 테스트만). 남긴 것: 되돌려도 폴더 지정과 선택 기록(`novel_folders`, `choice_logs` 등)은 복원되지 않는다. 라이브러리에 남은 표지는 전처럼 자동으로 지우지 않는다.
