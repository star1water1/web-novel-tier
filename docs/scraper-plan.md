# 플랫폼 스크래퍼 메모

작품 메타데이터를 원본 플랫폼에서 가져오는 기능의 설계 이유와 실측으로 알아낸 사실만 둔다. 구현은 `App.jsx`의 `fetchNovelMeta`, `searchNovels`, `scraperRefineByPlatform`, `parse*` 함수가 정본이다.
2026-06 시점의 상세 기록: `git show 042c87b:docs/scraper-plan.md`

## 설계 이유

- **LLM 검색 대신 스크래핑:** LLM은 마이너 작품에서 환각이 잦다. 원본 페이지의 값에는 환각이 없다.
- **프록시 불필요:** APK의 `fetch`는 네이티브 구현이라 CORS가 없어 폰에서 직접 호출한다.
- **파싱 방식:** RN에는 DOM 파서가 없다. `ld+json`, `__NEXT_DATA__`, OpenGraph 메타를 정규식으로 떼어 파싱한다. 마크업 셀렉터보다 덜 깨진다.
- **덮어쓰기 금지:** 가져온 값은 확인 모달에서 현재값과 비교해 고른 항목만 적용한다.
- **`read_count`는 가져오지 않는다:** 개인 독서 기록이다. 작품 전체 회차는 `total_episodes`다.
- **이용 범위:** 사용자가 요청할 때 1건씩 가져오는 개인용이다. 대량 수집, 결과 재배포는 하지 않는다.

## 플랫폼별 사실

| 플랫폼 | 제목 검색 | 메모 |
|---|---|---|
| 리디 | `ridibooks.com/search` SSR | 줄거리가 "{제목} 작품소개: {본문}" 형식이라 접두를 지운다 |
| 네이버시리즈 | `series.naver.com/search` SSR | |
| 문피아 | `mm.munpia.com` | `mm`만 구버전 SSR이다. `www`는 모바일 UA에서 `/main`으로 튕기고 `m`은 SPA다. 2자 미만 검색도 튕긴다 |
| 노벨피아 | `/proc/novel?cmd=novel_search` JSON | 상세 페이지가 SPA라 OG가 부실하다. 빈 검색어는 500을 준다 |
| 카카오페이지 | 외부 검색엔진 경유 | 자체 검색은 GraphQL·봇 차단으로 못 쓴다. 키가 있으면 Daum API, 없으면 DuckDuckGo·Brave 결과에서 `page.kakao.com` 링크를 모은다 |
| 네이버웹툰 | `comic.naver.com/api/search/all` | 웹툰 모드 |
| 카카오웹툰 | `searchKakaoWebtoon` | 웹툰 모드. 회차수는 로그인 WebView 응답 캡처로 얻는다 |

레진코믹스, 탑툰은 연재처 목록에만 있고 자동 검색은 없다.

플랫폼에는 키워드 없는 브라우즈·랭킹 API가 없다. 넷상 추천이 "키워드로 검색한 뒤 추리는" 구조인 이유다.

## 실측으로 알아낸 함정

- **비작품 JSON-LD:** 카카오 상세의 JSON-LD는 `Organization`뿐이다. 이걸 작품으로 집으면 모든 제목이 "카카오페이지"가 된다. 비작품 타입은 폴백에서 뺀다.
- **본문 텍스트 휴리스틱:** `/완결|연재중/`이 내장 JSON의 라벨까지 잡는다. 구조화 신호(`onIssue` 등)가 있으면 그쪽을 우선한다.
- **카카오 작품 구분:** 같은 `/content/{id}` 페이지에 웹소설과 웹툰화가 함께 실린다. URL의 id와 `seriesId`로 골라야 완결 오판이 없다.

## 검증 방법

- **개발 환경에서는 실측이 잘 안 된다:** 노벨피아는 데이터센터 IP를 막고(403), 문피아는 Cloudflare 챌린지를 건다. 폰의 주거망에서는 통과한다.
- **차단은 "정보 없음"과 구분한다:** `scraperDetectBlock`이 판별해 안내한다.
- **새 파서는 픽스처로 검증한다:** 폰의 '🔧 긁기 진단'이나 페이지 소스로 원본을 확보해 `docs/scraper-fixtures/`에 넣고 `docs/scraper-test.mjs`에 케이스를 추가한다.

## 보류

- **공유 시트 입력:** 라이브러리와 빌드 설정 변경이 필요하다. 클립보드 버튼(📋)이 같은 시나리오를 대부분 처리한다.
- **장르 별칭 매핑:** `mapScrapedGenres`는 공백·대소문자만 무시한다. "로판" 같은 별칭은 필요해지면 `normalizeTag`를 쓴다.
