기존 "웹소설 티어 랭킹 앱"에 **슬롯별 모드**(웹소설 ↔ 웹툰)를 도입한다.
티어/ELO/매칭/취향분석 등 핵심 엔진은 모드와 무관하게 공유하고, **작품 도메인 레이어**(플랫폼·장르/태그·용어·검색 소스)만 모드에 맞게 분기한다.

## 사용자 확정 사항 (질문 응답)

1. **검색 범위**: 1단계는 **자동검색 제외**, 모드 인프라부터. 작품 추가는 수동입력 + URL 붙여넣기 불러오기.
2. **장르/태그**: **웹툰 전용 세트로 분리**. 웹툰모드에선 웹소설 빌트인 장르를 숨기고 웹툰용 기본 세트 제공. (사용자 추가 태그는 유지)
3. **웹툰 플랫폼(연재처)**: 네이버웹툰, 카카오웹툰, 카카오페이지(웹툰), 레진코믹스, **탑툰** 포함.
4. **모드 정책(가정·확정 대기)**: 생성 시 선택 · 기본 웹소설 · 설정에서 변경 가능 · 모드 변경 시 기존 작품 데이터는 변환하지 않고 플랫폼/장르/용어/검색만 모드에 맞게 바뀜.

## 범위 경계

| 모드와 무관 (공유, 손대지 않음) | 모드 의존 (분기) |
|---|---|
| 티어 시스템·ELO·매칭 엔진·하이브리드 검증 | 연재처(플랫폼) 기본 세트 |
| 좌표계/스펙트럼 (이미 보편적: 강함/분위기/로맨스/전개) | 장르/태그 빌트인 세트 |
| 취향분석·수상·통계·백업/복원·클라우드 | 일부 UI 용어 라벨 |
| 슬롯/DB/app_meta 인프라 | 작품 검색 소스 게이팅 |

## 1. 데이터 모델 — 슬롯 `mode` 필드

- 저장 위치: `slot_meta.json`의 슬롯 레코드 (현재 필드: `id, name, uuid, createdAt, novelCount, lastAccessed` — `createSlot()` ~8987줄).
  - 추가: `mode: "novel" | "webtoon"` (기본 `"novel"`).
- 마이그레이션: 기존 슬롯에 `mode` 없으면 로드 시 `"novel"`로 간주(읽기 시 `slot.mode || "novel"`). 파괴적 변경 없음.
- 활성 모드 접근: 슬롯 전환(`performSlotSwitch` ~41109) 시 활성 슬롯의 `mode`를 모듈 변수 `globalSlotMode` + React state `slotMode`로 세팅. (darkMode/globalTierConfig가 슬롯 전환 시 세팅되는 패턴과 동일.)
- 설정에서 변경: 활성 슬롯의 `mode`를 토글 → `slot_meta.json` 갱신 + `globalSlotMode`/`slotMode` 갱신 + 플랫폼/장르 레지스트리 재적용. (재시작 불필요하게 설계, 단 일부 목록은 리로드.)

## 2. 슬롯 생성 UX — 모드 질문

- 현재: 설정→슬롯 탭의 단순 Alert "새 슬롯 생성" → `createSlot(null)` (~69343).
- 변경: 모드 선택 모달(웹소설 / 웹툰 2버튼 + 간단 설명) → `createSlot(name, mode)`.
  - `createSlot` 시그니처에 `mode` 인자 추가, 레코드에 기록.
- 슬롯 목록 UI(~69130): 각 슬롯에 모드 배지 표시("📖 웹소설" / "🎨 웹툰").

## 3. 플랫폼(연재처) 분기

- 현재: `FACTORY_PLATFORM_OPTIONS` (~18312) = 웹소설 6종, `platform_registry`(슬롯별)가 이를 시드.
- 변경: 모드별 팩토리 세트 도입.
  - `FACTORY_PLATFORM_OPTIONS_NOVEL` = 기존 6종.
  - `FACTORY_PLATFORM_OPTIONS_WEBTOON` = `["네이버웹툰", "카카오웹툰", "카카오페이지", "레진코믹스", "탑툰"]` (+ URL 맵).
  - `platform_registry`가 없을 때 시드값을 **활성 슬롯 모드**로 선택. (이미 슬롯별 레지스트리라 충돌 없음.)
- URL 맵(연재처 링크용):
  - 네이버웹툰 `https://comic.naver.com` · 카카오웹툰 `https://webtoon.kakao.com` · 카카오페이지 `https://page.kakao.com` · 레진코믹스 `https://www.lezhin.com` · 탑툰 `https://toptoon.com`

## 4. 장르/태그 분기 — 웹툰 전용 세트

핵심 제약(현 구조): `getAllMajorTags`/`getAllSubTags`(~13666)가 **빌트인을 항상 병합**. 빌트인 끄기 메커니즘이 (general 카테고리 외) 없음.

### 메커니즘 변경
- 팩토리 상수를 모드별로 분리:
  - `FACTORY_MAJOR_GENRES_NOVEL` / `_WEBTOON`, `FACTORY_SUB_GENRES_NOVEL` / `_WEBTOON`, (general/alias도 동일 패턴, 단 일부는 공유).
- `getAllMajorTags`/`getAllSubTags`가 **활성 모드의 팩토리 세트만** 병합하도록 수정(반대 모드 빌트인은 미포함). 사용자 추가 태그(`tagRegistry`)는 모드와 무관하게 유지.
- 좌표계/스펙트럼은 그대로(보편적).

## 5. 용어(UI 라벨) 분기

대부분 공통 사용 가능(연재중/완결/휴재/화/연재처는 웹툰도 동일). 모드 분기가 필요한 라벨은 소수:
- "웹소설" 직접 표기 지점 → 모드별 "웹툰"/"웹소설" (예: AI 키워드 프롬프트는 2단계 검색용이라 보류).
- 헤더/빈 화면 안내문 등에 "소설" 고정 표현 → `modeLabel`(웹소설/웹툰) 헬퍼로 치환.
- 추정 작업량 ~15–20개 라벨. (회차/화 등은 양쪽 동일하므로 변경 없음.)

## 6. 검색 소스 게이팅 (1단계: 자동검색 없음)

- 웹툰모드 슬롯에서는 기존 웹소설 사이트 자동검색(`searchNovels` ~17196, 5개 스크래퍼)을 **숨김/비활성**. (웹툰 슬롯에서 웹소설이 검색되는 혼선 방지.)
- 대체 경로: 수동 입력(제목/작가/플랫폼/태그) + URL 붙여넣기 `fetchNovelMeta`. 웹툰 URL 메타 파싱은 2단계.
- 웹 추천(`reco.web`)도 웹툰모드에선 비활성 또는 "수동 위주" 안내.

## 7. 마이그레이션·하위호환

- 기존 슬롯/데이터: 전부 `novel` 모드로 간주 — 동작 변화 없음.
- 백업/복원(JSON v9): 슬롯 모드는 slot_meta 영역 → 내보내기에 모드 포함, 가져오기 시 보존(없으면 novel).
- 클라우드 동기화: 슬롯 모드를 매니페스트/메타에 포함(없으면 novel). 표지/자산 로직 무관.

## 8. Phase 2 (별도, 본 문서 범위 밖)

- 웹툰 사이트 사이트별 검색 스크래퍼 (접근 가능 순: 네이버웹툰 → 카카오 계열 → 레진/탑툰). 각각 역공학·안정성 리스크.
- 웹툰 URL 메타 파싱(`fetchNovelMeta` 웹툰 분기).
- 웹툰 키워드 추천·자동수집.
